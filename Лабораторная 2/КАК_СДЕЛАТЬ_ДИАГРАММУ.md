# Как нарисовать UML-диаграмму инфологической модели

Диаграмму можно сделать двумя способами:

- **PlantUML** — диаграмма описывается текстом в файле `.puml` и рисуется автоматически;
- **Enterprise Architect / MySQL Workbench** — диаграмма рисуется мышкой (см. конец файла).

## 1. Установка PlantUML

Вариант А — без установки: открыть <https://www.plantuml.com/plantuml> или <https://www.planttext.com>,
вставить текст диаграммы, справа появится картинка, её можно скачать в PNG.

Вариант Б — в VS Code:
1. Установить Java (проверка: `java -version`).
2. В VS Code установить расширение **PlantUML** (автор jebbs).
3. Создать файл `model.puml`, написать текст диаграммы, нажать **Alt+D** — откроется предпросмотр.
4. Сохранить картинку: `Ctrl+Shift+P` → **PlantUML: Export Current Diagram** → `png`.

Вариант В — из командной строки: скачать `plantuml.jar` с <https://plantuml.com/download> и выполнить

```
java -jar plantuml.jar -charset UTF-8 -tpng model.puml
```

Рядом появится `model.png`.

## 2. Каркас файла

```plantuml
@startuml
!pragma layout smetana   ' встроенная раскладка, не нужен Graphviz
hide circle              ' убрать кружок «C» у классов
hide methods             ' у сущностей нет методов
skinparam linetype ortho ' линии под прямым углом

' здесь классы и связи

@enduml
```

Строки, начинающиеся с `'`, — комментарии.

## 3. Отношение = класс

```plantuml
class "clients\nКлиенты" as clients {
  PK id
  client_type
  full_name
  U unp
  phone
}
```

- В кавычках — подпись: `\n` переносит строку, поэтому латинское и русское имя выводятся в две строки.
- После `as` — короткое имя, по которому на класс ссылаются связи.
- В фигурных скобках — атрибуты, по одному на строку. Пометки `PK`, `FK`, `U` — просто текст.
  PlantUML их не проверяет, это обозначения для читателя.

## 4. Связи

Общий вид: `класс1 "кратность1" ТИП "кратность2" класс2 : подпись`

| Что нужно | Запись |
|---|---|
| Ассоциация 1:M | `clients "1" -- "0..*" devices` |
| С подписью и направлением чтения | `clients "1" -- "0..*" devices : владеет >` |
| Композиция (часть не живёт без целого) | `repair_orders "1" *-- "0..*" payments` |
| Необязательная связь (FK может быть пустым) | `employees "0..1" -- "0..*" repair_orders : ремонтирует >` |
| Рекурсивная (сама на себя) | `repair_orders "0..1" -- "0..*" repair_orders : гарантия по >` |
| M:N | через отношение-связь: две связи 1:M, например `repair_orders "1" *-- "0..*" order_services` и `services "1" -- "0..*" order_services` |

Кратности: `1` — ровно один, `0..1` — ноль или один, `0..*` — сколько угодно, `1..*` — хотя бы один.

Если между двумя классами две связи (у заказа есть приёмщик и инженер), пишутся две строки с разными подписями.

## 5. Порядок работы

Не пишите всё сразу — стройте модель по частям и смотрите предпросмотр после каждого шага:

1. Выписать из таблицы 1 (текстовая модель) все отношения и объявить классы с одним атрибутом `PK id`.
2. Добавить связи. Сразу видно, не осталось ли «висящих» классов.
3. Дописать остальные атрибуты: сначала `FK`, потом обычные.
4. Поправить внешний вид (раздел 6) и экспортировать PNG.

## 6. Если раскладка некрасивая

- Порядок объявления классов влияет на расположение: объявите рядом то, что связано.
- Длинная стрелка `---` вместо `--` отодвигает класс на уровень ниже.
- Можно подсказать направление: `clients -right- devices`, `-down-`, `-left-`, `-up-`.
- Невидимая связь для выравнивания: `positions -[hidden]- order_statuses`.
- Чётче картинка: `skinparam dpi 200`.
- Цвета: `skinparam classHeaderBackgroundColor #DFE9DF`, `skinparam classBackgroundColor #FFFFFF`.

Полная документация по диаграммам классов: <https://plantuml.com/ru/class-diagram>.

## 7. То же самое в Enterprise Architect

1. Создать проект, в модели добавить диаграмму типа **UML Structural → Class**.
2. Перетащить с панели инструментов элементы **Class**. Каждому дать имя `clients` и в псевдоним или
   заметку — русское имя.
3. Атрибуты: выделить класс → окно **Features → Attributes**, добавить атрибуты. PK/FK можно указать
   стереотипом или префиксом в имени.
4. Связи: инструмент **Association** (для частей заказа — **Composition**) протянуть от класса к классу.
   В свойствах связи на вкладках ролей **Source/Target** указать **Multiplicity** (`1`, `0..*` и т. д.).
5. Сохранить диаграмму как изображение (контекстное меню диаграммы → сохранить как изображение / Save as Image).

В MySQL Workbench получится ER-диаграмма (EER Diagram) с таблицами, а не UML-классы. Она ближе к
даталогической модели, так что для этой лабы (UML-форма инфологической модели) удобнее PlantUML или EA.
